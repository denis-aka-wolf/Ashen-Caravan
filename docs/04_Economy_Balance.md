# 04. Экономика и баланс

**Версия:** 2.0 · **Статус:** стартовые значения (гипотезы). Калибровать симуляцией (разд. 9) до кода и затем данными.

## 1. Принципы

1. Первая покупка — не позже чем через 10–15 с.
2. Окупаемость нового типа растёт плавно (×≈1.47 на тир): игрок всегда видит «следующую цель».
3. Рост экспоненциальный, но числа читаемы: сокращения и вехи ×2 на круглых количествах.
4. Prestige — ускорение, а не наказание: каждый перегон быстрее предыдущего.
5. Игра проходима без рекламы и покупок. RV ускоряет, но не блокирует (п. 4.5.2).

## 2. Генераторы

**Формулы** (тир *t*, 1..8):

```
base_cost(t)   = 10 × 12.5^(t−1)
base_income(t) = 0.5 × 8.5^(t−1)        [лом/с на 1 единицу]
growth(t)      = 1.10 + 0.01 × (t−1)     [от 1.10 до 1.17]
cost(t, n)     = base_cost(t) × growth(t)^n   [n = уже куплено]
```

| Тир | Название | Базовая цена | Доход/с | Рост цены | Окупаемость 1-й единицы |
|-----|----------|--------------|---------|-----------|--------------------------|
| 1 | Ручная тележка | 10 | 0.50 | 1.10 | 20 с |
| 2 | Велосипед-сборщик | 125 | 4.25 | 1.11 | 29 с |
| 3 | Мотодрезина | 1 562 | 36.1 | 1.12 | 43 с |
| 4 | Вездеход-сборщик | 19 531 | 307 | 1.13 | 64 с |
| 5 | Рой дронов | 244 141 | 2 610 | 1.14 | 94 с |
| 6 | Мобильная мастерская | 3.05 M | 22 185 | 1.15 | 138 с |
| 7 | Шагающий кран | 38.1 M | 188 575 | 1.16 | 202 с |
| 8 | Передвижной завод | 476.8 M | 1.60 M | 1.17 | 298 с |

### Покупка пачкой (сумма геометрической прогрессии)

```
cost_bulk(t, n, k) = base_cost(t) × growth^n × (growth^k − 1) / (growth − 1)
max_k = floor( log( 1 + money × (growth − 1) / (base_cost × growth^n) ) / log(growth) )
```

## 3. Вехи (доход типа ×2)

Купленных единиц: **10, 25, 50, 100, 200, 300, 400, 500**. На карточке: «до следующей вехи: N шт.».

## 4. Общий множитель дохода

```
income_total = Σ( count(t) × base_income(t) × milestone(t) × upgrade(t) )
               × global_upgrades × (1 + 0.02 × CR_total) × talents × temp_boosts
```

`CR_total` — все заработанные Чертежи. `temp_boosts` — «Золотая жила», дирижабль, RV-буст; суммарный временный множитель ограничить (**≤ ×10**).

## 5. Тап по находке

```
find_reward = max(1, income_total × 10) × find_power
find_power  = 1 + upgrades_finds + talent_luck
```

≈ 10 секунд дохода: заметно, но не ломает пассивный режим.

## 6. Prestige («Новый перегон»)

```
CR_gain = floor( sqrt( scrap_run_total / 1e7 ) )
```

| Лома за перегон | Чертежей | Бонус дохода (+2% × ЧР) |
|-----------------|----------|--------------------------|
| 1e7 | 1 | +2% |
| 2.5e8 | 5 | +10% |
| 1e9 | 10 | +20% |
| 1e11 | 100 | +200% |
| 1e13 | 1000 | +2000% |

- Первый перегон разрешён при `CR_gain ≥ 5` (≈ 2.5e8 лома).
- Цель: **первый перегон через 45–60 минут активной игры**.
- Следующие: порог достигается в 2–3 раза быстрее.

### Таланты (стоимость в ЧР)
```
cost_talent(level) = base × 2^level   (base: 3, 5, 8 в зависимости от ветви)
```

## 7. Офлайн

```
offline_scrap = income_total × min(elapsed, cap_seconds) × efficiency
cap_seconds   = (4 + talent_hours) × 3600      (макс. 12 ч)
efficiency    = 0.5 + upgrades (до 0.8)
```

- `elapsed` — серверное время SDK; минимум 60 с (не показывать окно при перезагрузке страницы).
- RV «×2» умножает итог, `efficiency` выше 1.0 не поднимает.

## 9. Калибровка

### 9.1. Таблица (Google Sheets / Excel)
Листы: `Constants`, `Crews`, `Milestones`, `Upgrades`, `Talents`, `Pacing`, `Sim`. Параметры — именованные ячейки.

### 9.2. Симуляция M1

Запуск: `npm run simulate -- --hours 1 --tap-every 10`. Симулятор использует игровое ядро и сейчас моделирует три стартовых тира, покупку наиболее выгодного доступного генератора, одну собранную находку через заданный интервал, вехи и офлайн-доход. Параметры `--hours` и `--tap-every` позволяют менять горизонт и частоту сбора находок. Результат — проверяемая базовая линия M1, а не прогноз поведения реального игрока.

Дальше расширять симуляцию вместе с соответствующими механиками: оставшиеся тиры, зоны, улучшения, просьбы и стратегия тапов. Использовать её, чтобы проверять целевой темп и подбирать баланс до выпуска.

## 10. Защита от багов и читов

- Время — серверное (SDK); при отрицательной дельте — игнор.
- Числа — через библиотеку больших чисел (`break_infinity.js` или аналог); при NaN/∞ — откат к последнему валидному автосохранению.
- Лидерборд принимает значения только в допустимом диапазоне темпа роста.

## 11. Формат больших чисел

`1 234` → `1.23K` → `1.23M` → `B` → `T` → `Qa` → `Qi` → `aa, ab, ac…`. Ширина текста резервируется, чтобы числа не «прыгали» и не накладывались (1.10.3).
