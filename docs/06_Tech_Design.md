# 06. Технический дизайн

**Версия:** 2.0 · **Статус:** на утверждение. Названия методов SDK перепроверить по актуальной документации перед реализацией.

## 1. Стек

| Слой | Выбор | Почему |
|------|-------|--------|
| Язык | TypeScript | Типобезопасность для экономики и сохранений |
| Сборка | Vite | Быстрая сборка, малый размер |
| Сцена | Phaser 3 | Параллакс, частицы, тапы, лёгкий вес |
| UI | HTML/CSS поверх канваса | Чёткий текст, адаптивность, локализация |
| Большие числа | `break_infinity.js` (или аналог) | Быстрее, чем произвольная точность |
| Тесты | Vitest | Юнит-тесты формул и сохранений |
| Локальный запуск | `@yandex-games/sdk-dev-proxy` | Тест с SDK с локального сервера (упомянут в release notes платформы) |

**Не берём:** Unity WebGL (тяжёлая загрузка, лимит 100 МБ и время старта), полноценный React для сцены.

## 2. Архитектура

### Текущий прототип

```text
src/
  core/        # независимые от браузера правила игры
    config.ts      # восемь тиров, зоны, улучшения, таланты и награды
    types.ts       # типы игрового состояния
    economy.ts     # цены, доход, bulk-покупки, улучшения и офлайн-настройки
    state.ts       # фиксированный тик, находки и воздушный дирижабль
    offline.ts     # начисление офлайн-дохода
    progression.ts # зоны, просьбы, достижения, prestige, таланты и награды
    save.ts        # localStorage, валидация и миграция формата сохранения
    simulation.ts  # симуляция прогрессии тиров и сбора находок
  scene/       # Phaser-сцена с серой дорогой, караваном и находками
  ui/          # DOM-интерфейс прототипа
  main.ts      # соединение ядра, сцены, интерфейса и платформенного слоя
  platform/
    types.ts          # платформенный контракт и данные лидерборда
    yandex-games.ts   # SDK Яндекс Игр и локальный fallback
scripts/
  simulate-economy.ts
```

Сборка и запуск — Vite; проверки ядра и SDK-адаптера — Vitest. Команды: `npm run dev`, `npm test`, `npm run build`, `npm run simulate`. В прототипе 8 тиров, 4 зоны, 34 улучшения, 12 талантов и 30 достижений. SDK Яндекс Игр интегрирован с локальным fallback; облачная синхронизация включается действием игрока, лидерборд отправляет суммарные Чертежи, rewarded-видео удваивает офлайн- и ежедневную награду. Настройки консоли, ограничения и оставшиеся интеграционные проверки описаны ниже.

### Целевая архитектура следующих этапов

```
src/
  core/        # чистая логика без DOM/Phaser
    state.ts       # GameState, версия схемы
    economy.ts     # формулы (см. 04)
    tick.ts        # фиксированный шаг расчёта
    offline.ts     # офлайн-доход
    prestige.ts
  systems/     # находки, дирижабль, просьбы, достижения, радио
  scene/       # Phaser: дорога, караван, параллакс, VFX
  ui/          # HTML-компоненты, панели, окна
  platform/    # адаптер платформы
    ysdk.ts        # реальный SDK
    mock.ts        # заглушка для тестов/локальной разработки
  i18n/        # ru.json, en.json, форматтеры
  save/        # сериализация, миграции, облако
  analytics/   # события (см. 08)
  config/      # базовые константы и схема удалённых параметров
```

**Правило:** `core/` ничего не знает о Phaser, DOM и SDK — чтобы тестировать экономику и считать офлайн без рендера.

## 3. Игровой цикл

- **Логика:** фиксированный шаг 10 Гц (100 мс), накопление `dt`; рендер — `requestAnimationFrame`.
- **Вкладка в фоне:** логика не симулируется шагами, а при возврате применяется формула офлайна (`04`, разд. 7).
- **Производительность:** целевые 60 FPS на десктопе, ≥ 30 FPS на бюджетных Android; параллакс — 3–4 слоя на атласах.

## 4. Интеграция SDK Яндекс Игр

| Требование | Реализация |
|-----------|-----------|
| 1.1 / 1.19.1 SDK подключён и инициализирован | На доменах Яндекс Игр загружается `/sdk.js`; на внешнем домене — только с `?yandex-sdk=1`; игровой запуск не зависит от SDK |
| 1.19.2 `LoadingAPI.ready()` | Вызывается после первой отрисовки и готовности ввода |
| 1.19.3 GameplayAPI | `start()` при старте/возврате, `stop()` при уходе из вкладки, потере фокуса или показе рекламы |
| 1.19.4 События паузы | `game_api_pause` / `game_api_resume` останавливают и возобновляют игровой тик |
| 2.14 Язык | Язык SDK пока не применяется; интерфейс прототипа остаётся RU |
| 1.3 Звук при потере фокуса | Звуковой движок в прототипе пока отсутствует |
| 4.7 Звук при рекламе | Игровой тик и GameplayAPI приостанавливаются на время rewarded-видео; аудиодвижок пока отсутствует |
| Облачные сохранения | Player data API; вход и первая синхронизация запускаются игроком, конфликт копий подтверждается диалогом |
| Серверное время | `ysdk.serverTime()` используется для ежедневного бонуса, офлайна и меток сохранения |
| Лидерборд | `ysdk.leaderboards.getEntries()` и `setScore()`; техническое имя по умолчанию — `best_navigators` |
| Удалённые параметры | `ysdk.getFlags()` с локальными default flags, версия схемы и диапазоны значений |
| Rewarded-видео | SDK callback `onRewarded` подтверждает удвоение офлайн-дохода или ежедневной награды |

### Адаптер
Все вызовы SDK идут через `src/platform/yandex-games.ts`, остальной код зависит от `GamePlatform`. Адаптер включает загрузку flags, server time, rewarded/fullscreen API, player data, лидерборды и игровые lifecycle events. SDK-типы соответствуют JavaScript API платформы; перед публикацией обязательна проверка на черновике в консоли Яндекс Игр.

### 4.1. Удалённое управление параметрами

- В v1.0 игра получает конфигурацию из remote-конфига: значения экономики и прогрессии, лимиты/эффективность офлайна, частоты и награды рекламных предложений, а также разрешённые переключатели событий и экспериментов.
- Для каждого параметра задаются тип, значение по умолчанию, безопасный диапазон и версия схемы. Некорректные, нестроковые или выходящие за диапазон значения отклоняются с записью ошибки; игра оставляет последнее валидное значение или использует встроенное значение по умолчанию.
- Конфигурация не исполняет удалённый код и не меняет структуру сохранения. Несовместимая версия схемы игнорируется.
- Конфиг загружается при запуске; игровой цикл не зависит от доступности сети. Экономические изменения не меняют формат сохранения.
- Схема 2: `tier_cost_multiplier` (0.5–2), `tier_income_multiplier` (0.5–2), `offline_cap_hours` (1–12), `offline_efficiency` (0.3–0.8), `prestige_scrap_per_blueprint_squared` (1 млн–1 млрд), `find_frequency_multiplier` (0.5–2), `airship_frequency_multiplier` (0.5–2), `plains_unlock_income` (1 тыс.–1 трлн лома/с), `flooded_unlock_income` (100 тыс.–10 трлн лома/с), `mountain_unlock_income` (1 млн–1 квадриллион лома/с), `order_refresh_seconds` (60–3600). Пороги дохода должны строго возрастать в порядке зон; несовместимые значения отклоняются.

## 5. Сохранения

### 5.1. Схема
```json
{
  "v": 3,
  "t": 1731312000000,
  "run": { "scrap": "1.2e8", "crews": [..8..], "upgrades": [..], "zone": 2 },
  "meta": { "cr": 12, "crTotal": 47, "talents": [..], "tokens": 85 },
  "orders": [...],
  "ach": [...],
  "radio": [...],
  "cosmetics": { "owned": ["..."], "selected": "..." },
  "settings": { "sound": true, "lang": "ru" },
  "stats": { "taps": 1204, "prestiges": 5 }
}
```
Большие числа хранятся строкой в научной нотации.

### 5.2. Правила
- Автосохранение: каждые 30 с, после значимых действий (покупка, перегон, награда), при `visibilitychange: hidden`.
- Миграции по `v`: функция `migrate(vOld → vNew)`; игра не должна терять прогресс при обновлении (1.9).
- Локальное сохранение в `localStorage` обязательно для гостевой игры; облачная синхронизация через Яндекс ID доступна по желанию игрока.
- При авторизации синхронизировать локальный и облачный прогресс по явно заданной политике слияния; при неоднозначном конфликте предложить игроку выбор, не перезаписывая молча более свежую копию.
- **Конфликт гость/облако:** выбрать запись с большим `meta.crTotal`, затем с большим `t`; показать игроку выбор, если разница значима.
- **Размер:** держать в десятках КБ; лимит SDK на данные проверить в документации.

## 6. Размер и загрузка

| Метрика | Бюджет |
|---------|--------|
| Распакованный размер | ≤ 100 МБ (требование 1.21); **цель ≤ 20 МБ** |
| Начальная загрузка | ≤ 5 МБ (gzip), играбельно за ≤ 4 с на среднем 4G |
| Текстуры | Атласы ≤ 2048×2048, WebP/PNG с оптимизацией |
| Аудио | OGG/MP3, музыка ≤ 1.5 МБ на трек |
| Шрифты | Подмножество Cyrillic + Latin |

Догрузка зон и тяжёлых ассетов — лениво, после Game Ready.

## 7. Адаптивность и ввод

- Логическая сцена 1080×1920 с «безопасными зонами»; масштабирование по короткой/длинной стороне.
- Десктоп: активное поле тянется до края; соотношение сторон поля ≤ 2:1 (1.6.2.1–1.6.2.2) — портрет 9:16 укладывается.
- Нет браузерной прокрутки и pull-to-refresh (1.10.2): `overscroll-behavior: none`, `touch-action`.
- Отключить системное контекстное меню и выделение в области игры (1.6.1.8, 1.6.2.7): `user-select: none`, `contextmenu` preventDefault.
- Клавиши по `event.code`, без зарезервированных ОС сочетаний (1.6.2.4, 1.6.2.6).
- Поддержка: Android 5.0+, iOS 9.0+ и десктопные браузеры из списка 1.20 — оценить на этапе M2; при невозможности — указать актуальный набор окружений в черновике.

## 8. Структура архива и файлов

- `index.html` в корне (1.22); имена файлов/папок латиницей без пробелов.
- Только относительные пути; не использовать абсолютные URL на S3 Яндекса (1.7).
- Видео (если будет) — внутри архива, не YouTube (3.9).
- Debug-панель только в dev-сборке (`import.meta.env.DEV`); в продакшене — вырезается.

## 9. Безопасность и надёжность

- NaN/∞-защита в `core/`: валидатор состояния после каждого тика (в dev) и при загрузке.
- Анти-чит: серверное время, разумные потолки множителей, проверка лидерборда.
- Реклама: никаких своих «рекламных» окон (1.16); вызов — только SDK.
- Обработка закрытия вкладки во время рекламы: награда выдаётся только по колбэку `onRewarded`.
