# 08. Аналитика и KPI

**Версия:** 2.0 · **Статус:** план. Все целевые значения — гипотезы, не бенчмарки платформы.

## 1. Цели аналитики

1. Понять, где игроки уходят в первые 5 минут.
2. Подобрать темп экономики и первого «Нового перегона».
3. Подобрать частоту рекламы без потери удержания.
4. Следить за стабильностью (ошибки, зависания).

## 2. Каналы данных

| Канал | Что даёт |
|-------|----------|
| Метрики консоли Яндекс Игр | Рейтинг, аудитория, удержание, доход, показы рекламы |
| Внутренние события (дебаг-лог + счётчики в сохранении) | Воронки, экономика, эксперименты |
| Яндекс Метрика | Использовать, только если допустимо по актуальным правилам платформы — проверить |
| Фидбек игроков | Отзывы в каталоге, чат разработчиков |

> Не собирать персональные данные. Для авторизованных использовать только идентификатор игрока из SDK. Политика конфиденциальности — текстом внутри игры, если нужна (3.5).

| `first_tap_find` | t_s | Первый тап |
| `buy_crew` | tier, qty, scrap_after | Покупки |
| `buy_upgrade` | id | Улучшения |
| `zone_unlock` | zone_id, t_run_s | Темп |
| `order_complete` | order_id, type | Просьбы |
| `find_tap` | combo | Активный слой |
| `airship_tap` | reward_type | Дирижабль |
| `prestige_view` | cr_gain | Увидел окно |
| `prestige_confirm` | cr_gain, run_time_s, prestige_n | Перегон |
| `talent_buy` | id | Мастерская |
| `offline_popup` | away_s, scrap | Возврат |
| `rv_offer_shown` | placement | Показан плейсмент |

## 4. Воронки

| Воронка | Шаги |
|---------|------|
| FTUE | game_ready → первый тап → 1-я покупка → 2-й тир → 1-я просьба → 10 минут |
| Prestige | зона 2 → зона 3 → prestige_view → prestige_confirm → 2-й перегон |
| RV | offer_shown → click → complete |
| Возврат | D1 → D3 → D7 → D14 |

## 5. KPI (гипотезы)

| Метрика | Цель | Комментарий |
|---------|------|-------------|
| Загрузка до Game Ready | ≤ 4 с (4G) | Техническая цель |
| Ошибки на 1000 сессий | < 2 | Стабильность (1.14) |
| Дошли до 1-й покупки | ≥ 90% | FTUE |
| Дошли до 10-й минуты | ≥ 60% | Удержание в 1-й сессии |
| D1 | ≥ 35% | Для idle-жанра ориентир, гипотеза |
| D7 | ≥ 12% | Гипотеза |
| Средняя сессия | ≥ 5 мин | Гипотеза |
| Сессий в день | ≥ 3 | Идут короткими заходами |
| RV на DAU | 1–3 | Гипотеза |
| Дошли до 1-го перегона (D3) | ≥ 40% | Показывает глубину |
| Рейтинг платформы | > 30 к 3 неделе | Требование 2.13 |

## 6. A/B через remote-флаги

| № | Эксперимент | Варианты | Метрика успеха |
|---|-------------|----------|----------------|
| E1 | Задержка первого interstitial | 3 / 5 / 8 мин | D1, сессия |
| E2 | Интервал interstitial | 120 / 180 / 240 с | D7, ARPDAU |
| E3 | Порог 1-го перегона | 3 / 5 / 8 ЧР | Доля дошедших до 2-го перегона |
| E4 | Находки вкл/выкл | с активным слоем / без | D1, длина сессии |
| E5 | Награда RV буста | ×2 / ×3, 4 / 6 мин | Доля принятия, D7 |
| E6 | Лимит офлайна | 4 / 8 / 12 ч | Возвраты |

Правила: один эксперимент за раз на метрику; минимум ~1000 игроков на вариант до выводов (иначе только качественные выводы).

## 7. Дашборд (еженедельный)

1. Воронка FTUE и точки отвала.
2. Удержание D1/D3/D7.
3. Темп прогрессии: медианное время до зон и перегонов.
4. Реклама: RV на DAU, интервал interstitial, влияние на удержание.
5. Ошибки и устройства с проблемами.
6. Отзывы и оценки (темы жалоб).

## 8. Порядок работы после релиза

1. Недели 1–2: только исправление багов и калибровка через флаги; рейтинг игры формируется (первые ~2 недели не учитываются).
2. Неделя 3: проверить рейтинг > 30 (иначе — угроза снятия по 2.13); решать по метрикам.
3. Далее: гипотезы по таблице E1–E6, релизы раз в 1–2 недели.
