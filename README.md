# Пепельный караван — игровой прототип

Игровой вертикальный срез на серых блоках с основными механиками v1.0: 8 тиров техники, 4 зоны, находки, улучшения, просьбы, prestige, таланты, ежедневные награды, достижения, косметика, радио и офлайн-доход. Реализован адаптер SDK Яндекс Игр с локальным fallback, удалённой настройкой экономики, добровольной облачной синхронизацией, глобальным лидербордом и rewarded-видео для удвоения офлайн- и ежедневной награды.

Порог 10 единиц предыдущего тира для открытия следующего — стартовое балансировочное допущение. Новые зоны становятся доступны по порогам дохода; игрок подтверждает переход кнопкой, а шкала показывает прогресс маршрута. Текущие пороги управляются Remote Config и описаны в `docs/06_Tech_Design.md`.

На локальном `npm run dev` игра работает без SDK и сохраняет прогресс в `localStorage`. На доменах Яндекс Игр SDK загружается из `/sdk.js`; для теста на другом домене можно добавить `?yandex-sdk=1`. Без SDK глобальные сервисы и кнопки rewarded-видео скрыты.

Для лидерборда создайте в консоли Яндекс Игр таблицу с техническим именем `best_navigators` либо задайте другое имя через `VITE_YANDEX_LEADERBOARD_NAME`. Просмотр общего топа и отправка суммы Чертежей доступны на вкладке «Топ»; отправка требует авторизации Яндекс ID. Облачная синхронизация запускается игроком вручную на этой же вкладке; при существенном конфликте локальной и облачной копий игра предлагает выбор. После согласия облачная копия автоматически обновляется раз в минуту.

Remote Config Яндекс Игр считывается при запуске. Поддерживаемые флаги, их типы и безопасные границы описаны в `docs/06_Tech_Design.md`. Rewarded-видео выдаёт удвоение только после SDK callback `onRewarded`; доступны удвоение офлайн-дохода и ежедневного бонуса. Рекламные плейсменты нужно включить и проверить в консоли перед публикацией.

## Требования

- Node.js 22.18 или новее
- npm 10 или новее

## Установка и запуск

```powershell
npm install
npm run dev
```

Откройте локальный адрес Vite, напечатанный в терминале.

## Проверки и production-сборка

```powershell
npm test
npm run build
npm run preview
```

Сборка создаётся в `dist/`. `npm run build` сначала выполняет строгую проверку TypeScript, затем собирает браузерную версию.

## Симуляция экономики

Симулятор использует то же ядро, что и игра, все 8 тиров и пороги дохода для зон. В отличие от игры, он автоматически подтверждает переход, когда порог достигнут. Базовый сценарий моделирует покупку генератора с минимальной окупаемостью и сбор одной находки через заданный интервал.

```powershell
npm run simulate
npm run simulate -- --hours 4 --tap-every 15
```

В отчёте выводятся времена достижения контрольных количеств техники, состав каравана, доход в конце периода и оценка четырёхчасового офлайн-дохода. Симулятор пока не моделирует случайные события, выполнение просьб, покупку улучшений и престиж; результаты — инструмент калибровки, а не гарантированный игровой темп.

## Структура

```text
src/
  core/       Чистая экономика, состояние, находки, офлайн, сохранение, симуляция
  scene/      Phaser-сцена дороги и находок
  ui/         DOM-интерфейс прототипа
  main.ts     Связка состояния, сцены, UI и localStorage
scripts/
  simulate-economy.ts
```

`src/core/` не импортирует Phaser или DOM и проверяется Vitest. Прогресс хранится локально в браузере и мигрирует со старого формата сохранения. Базовый офлайн — 4 часа с эффективностью 50%; таланты и улучшения могут поднять значения по игровым ограничениям. Числа пока используют `number`, поэтому прототип не рассчитан на экономику с астрономическими величинами idle-игры.

Интеграция SDK изолирована в `src/platform/`. На локальной машине без SDK функции облака, лидерборда и рекламы не эмулируются; это не мешает запуску и тестированию ядра.
